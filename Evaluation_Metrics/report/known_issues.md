## 3. eval/evaluations.npz has no success array

EvalCallback stores only timesteps, returns and episode lengths. The eval success-rate curves are computed from `monitor_eval.monitor.csv`, which has a `success` column (one row per eval episode, in eval-call order).

## 4. Every original run used the same training seed

Training seeds found in hyperparams.json of all 18 runs: [0]. Variability across training seeds is measured only by the optional multi-seed runs in `multiseed_runs/`.

## 5. Live_Demo `--save` writes into tracked files

`demo_core/animate.py` saves to `Live_Demo/backup/gifs/<name>.gif` with a fixed name per demo, which would overwrite tracked backup GIFs. The videos are therefore rendered by importing the demos as a library and redirecting `demo_core.paths.out_dir` at runtime to `Evaluation_Metrics/videos/raw/`. No Live_Demo file is edited (checked by tests/test_eval.py).

## 6. Fields the environment does not report

- `out_of_bounds` in `info` is a per-step flag and is always False in supervise/full modes (OOB moves inside an Explore option are not reported). `ScenarioEnv` counts them with a hook on `_nav_step`.
- There is no battery-empty flag. It is derived as `battery <= 0` at episode end, which is exactly the env's own termination test (`self.battery <= 0`).
- In supervise/full modes `steps` counts supervisor decisions; low-level steps are counted separately (`low_level_steps`).
